01 / About

Backend engineering, without the noise.

I focus on what decides whether a system works outside a demo: clear ownership, safe retries, predictable data flow, useful monitoring, and simple failure handling.

How I work

I start with the request path, the data, and what can fail. Then I keep the design as simple as the problem allows. I care about readable code because production systems are maintained far longer than they are built.

Make failure visibleTimeouts, retries, fallbacks, and useful logs belong in the design.
Protect the data pathOrdering, duplication, caching, and consistency are never afterthoughts.
Keep it understandableA strong service should be easy for the next engineer to operate and change.
